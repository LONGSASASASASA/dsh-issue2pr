Guide

工作流说明

说明页从介绍插件改为教会使用者决策：先理解与规划，再实施与交付。

Phase A

理解与规划

  • 01P01 把 Issue 提炼为结构化契约，成功标准必须可验证。
  • 02P02 到 P04 逐步收敛：候选文件、调用链、根因假设。
  • 03P05 生成 TaskGraph，是第一个必须认真复核的关卡。

Phase B

实施与交付

  • 04P06 产出候选修改，P07 校验基线后才落盘。
  • 05P08 必须真实执行测试，结果不允许由模型编造。
  • 06P09 与 P11 分别完成审查门控和交付评测。

Safety

边界规则

  • A基线不一致时拒绝应用 patch，避免覆盖他人修改。
  • B每条 patch 进入 ledger，可追踪也可单独回滚。

Failure

失败路径

  • C失败进入 P10 分类，不走盲目重试。
  • D根因错误回到规划，测试选择错误补测试，权限问题升级人工。

左侧保持目录心智，右侧专注阅读。JSON 与 Markdown 的元信息放入工具条，内容区只承担内容本身。
