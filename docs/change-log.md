# 修改记录

## 记录协议

格式：
- 修复：`序号.修复【范围】：存在 xxx 问题，修复后 xxx。`
- 其他：`序号.类型【范围】：原行为/新增内容 xxx，调整/新增后 xxx。`

类型：修复 / 新增 / 调整 / 删除 / 文档 / 测试

规则：
- 本文件仅记录正式代码的变更；方案文档、原型、设计稿等非正式开发产物及其调整不记录
- 同一次修改及其配套测试合并为一条记录，独立修改分别记录
- 修复类必须描述“原问题 + 修复后结果”
- 其他类型描述“原行为/新增内容 + 最终效果”
- 不记录排查过程
- 不写大段实现细节
- 序号持续递增，不重新编号

81.新增【通用留档基础设施】：原留档要么整文件覆写、要么无限追加，大日志受内存上限约束且异常退出后无从判断完整性；新增 journal 持续写盘模块——分片按大小阈值轮转、只增不删不截断，单条 JSON 记录不跨分片、超大单条独立原子落盘，流式片段经有界缓冲持续写盘（按大小、显式 flush 与记录前三类触发点）；manifest 清单每条记录即原子更新，携带 schemaVersion、执行身份与分片顺序；原文引用统一 path/offset/length/sha256/encoding 字节级定位，读取端校验行边界与 UTF-8 完整性，超限明确报错不截断；完整性为一等字段（complete/partial/unavailable/write_failed/corrupt，open 为运行态扩展），只由写入事实判定、调用方不得自报；写盘失败后中止追加并封存 write_failed，业务异常与留档故障分开保留互不覆盖；异常退出经 recover 封存 partial（unobserved_end），采纳未登记分片、保留半行原文；单写者目录归属，未闭合、已封存或含游离分片的目录拒绝写入。全量 479 项测试通过，含 14 项新增 journal 用例（轮转不截断、跨 UTF-8 边界、超大 blob、只读分片与清单目录故障注入、半行恢复、缺失分片与索引损坏、引用防御）。
82.新增【内置 LLM 全过程留档】：原内置阶段调用模型只留摘要事件、完整请求响应无从回溯，新增每次真实请求建独立 journal（trace/llm/<callId>/<attemptId>/）——请求发送前持久化实际传入的 system/user 与生效参数（provider、model、reasoningEffort、maxTokens、timeoutMs；不序列化 API Key、认证对象、请求头、环境变量），快照失败即中止调用（请求不发出）；响应流式片段经有界缓冲持续落盘，结束后保存完整正文、原始与归一化 finish reason、usage（宿主未暴露明确标记 unavailable）；JSON 提取、schema 校验等处理步骤连同原文引用一并留档。悬浮助手等无 Run 场景不留档。
83.新增【LLM 稳定错误分类】：原模型失败只有字符串消息、超时与格式错误难以区分，新增五类互斥稳定错误码——llm_call_failed（细分 llmCause：timeout/provider/cancelled/empty/unknown）、output_truncated（明确 token/length/incomplete 结束原因优先于 JSON 处理判定，文本碰巧可解析也不当成功）、json_parse_failed、schema_validation_failed、business_gate_failed；错误对象可序列化（toJSON 白名单），调用身份与留档目录事后附着、序列化后不丢字段。
84.新增【契约 schema 校验】：原 JSON 契约只查顶层必填字段、嵌套结构非法流入下游，新增声明式输出 schema 校验（类型 string/number/boolean/object/array，约束 required/enum/properties/items 支持嵌套数组与对象），问题消息以 JSON 路径定位（如 $.candidates[0].confidence），稳定可读且不截断内容，格式修复重试可直接携带 schema 与具体错误。
85.新增【有限重试】：原输出非法或截断直接失败，新增一次逻辑调用最多两次真实请求的有限重试——首次 JSON/schema 格式错误触发唯一一次「格式修复」重试（独立修复指令，只携带目标 schema、具体错误与上次原始输出，不重发原业务长 prompt）；首次输出截断在 32768 token 硬上限内提升一次输出预算后重发原业务请求（预算变化记入 retryReason 与留档）；timeout、provider 服务错误、取消、有效业务 fail 均不重试；第二次仍失败保持失败不补造，最终错误携带完整 retryHistory。全量 510 项测试通过。
86.修复【P10 失败归类】：存在模型协议错误、调用故障与业务验收失败混为一谈、重启后无证据可用、历史评测报告可能被新一轮复用的问题；修复后阶段失败以结构化错误（st.errorInfo：code/llmCause/finishReason/callId/attemptId/logRefs/retryHistory）随 run.json 持久化，重启后 P10 确定性读取；归类先走结构化规则——协议错误类→模型协议错误、llm_call_failed 按 llmCause→超时/服务错误/取消/空响应/调用失败、business_gate_failed→实现错误（有效业务验收失败），无断言证据或业务门禁支撑的「实现错误」不采信改判原因未确定并升级人工，模型只补充 analysis 不产生结论；P11 评测报告绑定本轮 stageExecutionId，属于上一轮的报告明确拒绝。全量 519 项测试通过。
87.新增【Claude 委外留档】：原 claude 执行只存单个 external-exec.log 镜像、进程中断后完整性无从判断，新增 stdout、stderr、records 三类独立 journal 单写目录持续落盘，任务包引用 sha256 登记；退出判定改从盘上读取（内存兜底），outcome 明确标注各路来源与留档完整性（stdoutSource= disk/memory 及 integrity），留档故障不伪装成功。
88.新增【DSH 原生实时采集】：原 DSH 委外执行只在结束后一次性读取事件、初始静默等待超时会跳过整个采集，修复后按轮询实时接收事件流并即时落盘，firstSeq 边界在等待期也正确建立，超时与取消前已收到的内容保留；平台未暴露的过程字段明确标注不可观测，不推测补造。
89.新增【留档追溯读取与展示】：原摘要事件无完整日志引用、外部 Agent 索引单文件无限增长、超限产物无法完整获取、页面错误不分类型。修复后：trace/events.jsonl 摘要事件增加 logRef（journal 目录）与 logIntegrity（完整/部分/写失败/损坏/未封存）透传，正文全文仍不进摘要；外部 Agent messages/events 超过 8MB 轮转新分片（首片沿用既有文件名，索引条目 source.file 指向实际分片，分片清单原子登记、损坏或登记分片缺失时明确报错，清单缺失按文件名枚举兜底；旧格式无 file 字段按首片读取兼容，跨分片定位与工具调用关联同样校验）；artifact 接口新增 download=1 字节流完整下载（无大小上限、防 .. 逃逸同口径，预览的 200KB/5MB 限制只约束查看不反向变成存储截断）；页面阶段错误条按结构化错误显示类别徽标（协议错误/调用错误含 llmCause 细分/业务验收失败/留档不完整）与留档目录引用，超限产物与日志面板提供完整文件下载链接，事件摘要行标注留档完整性。全量 527 项测试通过（两轮连续全绿；其中 P8 超时用例的计时断言边界由 2.5s 放宽至 4s，仍远低于子进程自身 10s 退出以保持「kill 及时生效」的判别力）。
90.修复【异常路径留档补全】：存在四类失败路径的异常日志未保存或不被引用的问题——委外执行失败抛错不携带留档引用（journal 已落盘但 errorInfo.logRefs 为空、执行器观测的失败事实丢失）、开工前 clone/工作区准备失败无结构化错误（P10 落「原因未确定」）、阶段异常栈轨迹未留存、P10 自身失败仅在报告留 analysisError 而 run.json 无 errorInfo（页面无类别徽标）。修复后：claude/dsh 执行器 outcome 暴露 journal 目录（runDir 相对、统一 / 分隔，journal 未建立为 null 不虚构）与封存完整性，P6 失败抛错附着 failureKind（spawn/timeout/result-error/exit/empty/agent）+ logDirs + 最差留档完整性，经 structuredErrorOf 贯通进 st.errorInfo 并去重有界；阶段失败摘要事件（pipeline 失败事件与 P6 执行未完成事件）携带 logRef 与 logIntegrity；structuredErrorOf 新增异常栈有界保存（≤4000 字）与 logDirs/failureKind 透传；failRun 支持结构化 errorInfo，drive 的仓库准备失败写 environment_error，P10 据此确定性归类「环境缺失」，委外 spawn→环境缺失、timeout→执行超时（LLM 只可补充解释）；P10 自身失败也落 st.errorInfo（含 sourceStage 与异常栈，原始诊断仍由 09 报告 evidence 保留）。页面新增「环境错误」「外部执行失败（含形态细分）」徽标（可与留档不完整叠加），事件摘要行的日志引用缩短为末两段身份。全量 531 项测试通过（两轮连续全绿），新增 4 项用例并扩展 6 项既有断言，覆盖 claude/dsh 双执行器引用贯通、P10 新确定性分类、异常栈保存与徽标映射。
91.新增【P1 目标契约】：原 P1 契约无 goal 字段、目标语义分散在 phenomenon 与 success_criteria 中，新增必填 goal（一句话北极星目标，默认提示词约束写法：动词开头、含对象模块、含可判定完成状态）与可选 non_goals（圈定不做的范围），P1 委外输出契约同步；goal 成为全流水线目标的唯一权威载体，缺 goal 返回 schema_validation_failed，存量 run 无该字段不受影响。
92.新增【目标投影函数】：原各阶段无统一的目标注入出口，新增 helpers.goalBriefOf 机械投影——读盘 01 契约拼接目标+成功标准（≤8 条）+约束（≤8 条）+非目标（≤5 条）与固定边界声明（目标仅供理解与验收对照、范围以任务节点/派单为准、节点外问题记录上报不自行修改），条数超限与 2K 字符硬顶均截断并显式标注；旧 run 无 goal 由 phenomenon+scope 兜底并标注，01 缺失或损坏返回空投影不阻塞阶段；支持轻量形态（仅目标一句+边界）。纯机械拼接无二次 LLM 加工，同输入同输出。
93.新增【决策层目标注入】：原 P3/P4/P5 的 prompt 完全看不到 P1 目标契约（P3 被要求按 Issue 关联度排序却无目标可对照、P4 假设筛选与 P5 拆分无源头判据），调整后三阶段 prompt 头部注入完整投影，措辞为背景语气（【全局目标（背景，仅供理解与验收对照）】）而非授权语气；每次执行读盘注入不缓存，P1 重跑后目标自然更新，旧 run 无 01 时不注入不报错。
94.新增【P6 分层目标注入】：原 P6 三条路径只看任务图、coder 与委外对原始目标无感知，调整后按角色分层——派单 planner 注入完整投影（节点→文件为方向性映射）；builtin coder 只注入轻量形态（goal 一句+边界，不含标准/约束明细，防目标诱发扩权）；session 任务包与 claude/dsh 委外执行 prompt 注入完整投影+边界声明（委外可见全仓库、自主性强，边界必须显式）。委外产物契约不变。
95.新增【委托任务包目标输入】：原 P3/P4/P5/P9 委外任务包与本机执行看到的目标不一致（委外完全无目标），新增 goal 输入令牌（delegateSpec.inputs，与 trigger/failure/repo 特殊输入同风格），buildDelegateTask 据此渲染目标投影而非 01 全文，与本机执行同口径；P2 委外读 01 全文的既有行为不变。
96.测试【目标注入回归】：新增 9 项用例——goalBriefOf 完整投影与确定性输出、条数与 2K 截断标注、轻量形态不含标准/约束明细、旧 run 无 goal 兜底与 01 缺失空投影、P3/P4/P5 prompt 头部注入（含旧 run 不注入）、P6 派单完整投影与 coder 轻量形态分层、session 任务包与 claude 执行 prompt 含完整投影+边界、委托任务包 goal 令牌渲染；P1 契约用例同步更新断言 goal 与 non_goals 落盘。全量 540 项测试通过。
