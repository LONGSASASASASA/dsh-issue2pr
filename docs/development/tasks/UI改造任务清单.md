# UI 改造 Task 清单

依据 v9 原型改造正式 Issue2PR 插件 UI，共 6 个 Task。细项通过任务内勾选清单管理。
本文定义实施与验收要求，任务状态不代表功能已经实现；已按用户授权开始正式代码改造，验证结果随任务更新。

## 1. 改造基准与范围

- 界面基准：[issue2pr-ui-prototype.html](../../design/一期原型/issue2pr-ui-prototype.html)，即正式归档的 v9 原型。
- 设计背景：[issue2pr-studio.html](../../design/issue2pr-studio.html)。阅读或修改设计目录内容时遵守该目录的 [AGENTS.md](../../design/AGENTS.md)。长期设计不等于本轮实施范围。
- 正式前端：[client.js](../../../client.js)，沿用 DSH 模块加载、宿主 React 和现有插件入口。
- 后端接口：[index.js](../../../index.js) 中的 `/issue2pr/api`；状态和产物以现有流水线、存储及执行器的真实结果为准。
- 本地联调：[DSH 插件本地开发](../guides/dsh-plugin-local-development.md)。实施时先检查实际链接和宿主环境，再决定是否需要调整。
- 变更记录：[change-log.md](../../change-log.md)，遵守其记录协议。

### 硬性约束

1. **保持 v9 配色**：沿用归档原型的明暗主题颜色值和语义映射，包括背景、面板、文字、边框、强调色及状态色；不另行调整色系。适配宿主主题时只映射主题选择，避免宿主样式覆盖原型配色。
2. 页面结构和主要交互对齐 v9，原型中的 DSH 导航示意由宿主真实导航承担；演示工具栏、场景切换和模拟推进不进入正式界面。
3. 正式界面的状态、日志、统计、文件和验证结论必须有真实数据来源；测试样例仅用于测试与预览。
4. 保持现有 P1—P11 流水线语义，P10 按失败旁路展示；界面“任务”映射现有 Run，执行实例或子任务与 Run 明确区分。
5. 保留现有正式功能及其操作入口。优先复用接口、状态管理和宿主组件，避免无关重构或未经验证的加载、打包方式变更。
6. 在 `develop` 分支实施，排除根目录 `AGENTS.md` 的本地修改；不修改本地 `main` 的提交位置，不向远程 `main` 推送。提交前逐项核对文件，提交、推送按当时授权执行。
7. 行为变更补充相关验证，正式代码变更记入 `docs/change-log.md`；任务清单、方案和原型自身的调整不记入正式代码变更记录。
8. **全局配置与运行逻辑同步改造（用户补充授权）**：项目只在新界面中管理仓库、名称和来源；新任务统一读取全局执行配置，启动时保存配置及宿主默认模型快照。推进、复核、重跑和委外监听均使用任务快照；没有快照的历史任务兼容读取旧项目配置。连接凭据单独保存，不复制秘密到任务快照。

## 2. Task 协议

### 固定字段

| 字段 | 填写要求 |
| --- | --- |
| 编号与名称 | 使用 UI-01 至 UI-06；名称描述具体成果 |
| 状态 | 待开始／进行中／阻塞／待验收／已完成 |
| 目标 | 描述用户最终能看到或完成什么 |
| 前置依赖 | 写明必须先完成的任务编号；可独立开展的准备工作不必等待 |
| 实施范围 | 写明页面、代码、接口及排除项；新增接口必须说明现有接口缺口 |
| 执行清单 | 使用勾选项；完成后才能勾选，不以计划替代结果 |
| 验收与验证 | 列出可检查条件、适用测试和宿主验证方式 |
| 完成记录 | 记录修改文件、验证命令与结果、遗留问题、提交号（如有） |

### 状态与执行规则

- 开始实施时改为“进行中”，交付可审阅成果后改为“待验收”；完成实施清单及适用验收后才可标记“已完成”。
- 遇到确需外部条件的问题时记录阻塞原因、影响范围和解阻条件；不受影响的工作继续开展。
- 每次状态变化同步更新总览和对应任务，完成记录保留失败及修复后的验证结果。
- 任务中的“已完成”指本轮约定范围完成，不代表长期设计全部落地。
- 常规实现细节按项目惯例处理；需要改变明确产品行为、架构方向或扩大范围时，先说明证据、推荐方案及取舍，再由用户决定。
- 验证失败不能通过删除有效断言或将未完成项转为“通过”处理；尚未具备真实宿主条件时明确记录，不以预览测试代替宿主验收。
- 开发阶段可按任务形成独立提交；执行提交时采用仓库现有 Conventional Commits 格式，不将提交数量作为完成条件。

### 全局配置协议

- 存储：数据根目录 `settings.json`，包含 `version`、递增 `revision`、复核方式、P6 模式、测试命令、最多打回次数和 `stageConfig`。
- 更新：`GET /settings` 读取；`PUT /settings` 校验后原子写入。携带旧 `revision` 保存返回 409，界面保留草稿，支持重新载入。
- 首次使用：没有文件时返回系统默认，不擅自选某个项目覆盖全局；界面可将指定旧项目的执行设置导入草稿，再由用户检查并保存。
- 新任务：创建前解析全局设置与宿主默认模型，保存到 `run.executionConfig`；项目只提供仓库、名称和来源。
- 执行：普通推进、复核、重跑、委外监听和 DSH 原生智能体采用任务快照；阶段模型覆盖高于启动时默认模型。Claude 自身模型仍由其执行器配置决定。
- 兼容：没有 `executionConfig` 的历史任务继续读取旧项目执行字段；更新项目元数据保留旧字段，不再要求停用的历史执行器可用。
- 凭据：Git 连接及中转令牌独立保存，运行时读取当前凭据，不复制到任务快照。
