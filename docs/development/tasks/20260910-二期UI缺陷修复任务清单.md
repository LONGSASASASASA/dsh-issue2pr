## P0 状态语义（核心）

### S1 验收门禁「未通过」与「通过」视觉零区分

- [x] S1 修复完成

**现象**：完成任务 P11 卡片的六项验收门禁（根因证据/补丁应用/回归测试/变更审查/说明忠实/验收门禁）中，「通过」与「未通过」渲染结果完全相同。

**真实宿主证据**（DOM 实测）：六个值全部为 `span.hint`、`color: rgb(89,104,117)`、`font-weight: 400`、无图标、无背景。视觉模型对截图独立得出相同结论：「必须逐行阅读文字才能发现有未通过项」。

**修复方向**：门禁值按结果分色——「通过」用现有成功色（绿），「未通过」用失败色（红/橙）+ 字重提升；值为未通过时行内加 ✕/⚠ 图标。位置：client.js P11 卡片门禁 kv 渲染处（值统一套 `hint` 类的逻辑）。

**验收标准**：
1. 真实宿主打开完成任务 20260905-205334-37，DOM 实测「未通过」值颜色 ≠ 「通过」值颜色，且含图标或字重差异；
2. 截图盲看 3 秒内能指出存在未通过项；
3. 深色主题下两色均满足对比度 ≥ 4.5:1。

### S2 同卡片自相矛盾的状态叙事

- [x] S2 修复完成

**现象**：同一张 P11 卡片上并存三层成功信号（任务级绿徽章「已完成」→ 阶段级绿徽章「已通过」→ 底部文案「本轮阶段已通过」），而六项门禁里 3 项「未通过」（含名为「验收门禁」的那项本身）。

**真实宿主证据**：视觉模型原话「页面最显眼的信号全是成功信号……信息自相矛盾，用户很可能误读为全部通过」。

**修复方向**：门禁存在未通过时，P11 卡片头部徽章改为中性/警示态（如「已交付 · 3 项门禁未通过」），尾部「本轮阶段已通过」文案改为汇总式（「6 项门禁：3 通过 / 3 未通过」）。与 S1 联动，同一处渲染逻辑。

**验收标准**：
1. 完成任务（含未通过门禁）卡片头部不再出现纯成功态徽章 + 「本轮阶段已通过」的组合；
2. 头部可见未通过计数；
3. 全部门禁通过的任务仍显示成功态（回归不破坏正向场景）。

## P1 折叠进度条

### S3 折叠进度条没有失败态

- [x] S3 修复完成

**现象**：失败任务折叠进度点序列中，失败阶段（P6）显示为蓝色「进行中」点（dots = `done×5, current, none×4`），与「正在执行」同形；默认收起时用户误读为卡住/进行中。展开轨道正常（P6 红底红 ×）。

1. 真实宿主打开失败任务 20260907-142755-37，折叠态 P6 点为红色系且区别于蓝色「进行中」；
2. 展开轨道行为不变；
3. 进行中任务的 current 点不受影响。

## P2 可达性

### S5 「•••」菜单关闭态内藏高危操作

- [x] S5 修复完成

**现象**：任务详情头部「•••」用 `<details>` 实现，首轮认为关闭态内控件可被 Tab 直达。

**修复期实测修正**（2026-09-10）：Chromium 关闭态 details 内容**原生不可聚焦**（`focus()` 失败、content-visibility 隐藏、不绘制）——「Tab 可达」不成立；真实缺陷为**展开后无 Esc 关闭、无点击外部关闭**（菜单悬停遮挡内容），已按此修复。

**修复方式**：details 改受控（open 受 React state），展开时注册 document 监听：Esc 关闭并聚焦 summary（stopPropagation 防止连带关闭工作台）、点击外部关闭。位置：client.js RunsPanel。

**验收标准**：
1. 关闭态 Tab 遍历不落入隐藏菜单项（原生成立，实测确认）；
2. 展开、选择「任务详情」跳转、「重跑/删除」交互行为与现状一致（仅增关闭行为，未改操作逻辑）。

### S6 重开面板焦点不归位

- [x] S6 修复完成

**现象**：关闭再重开工作台后，`document.activeElement` 停留在「关闭」按钮上（可见绿色 outline）。

**根因**（修复期定位）：打开时的 effect 主动聚焦 `.studio-toptools button:last-child`（即「关闭」按钮）——并非焦点未管理，而是聚焦目标选错。

**修复方式**：面板根 `.i2p-page` 加 `tabIndex:-1`，打开时聚焦面板根；首个 Tab 自然进入面板内首个控件；关闭时焦点还原入口按钮的原有逻辑不变。

**验收标准**：重开面板后 activeElement 不再是关闭按钮；键盘首个 Tab 落在面板内首个控件。

## P3 视觉连续性

### S4 阶段连线视觉近不可见

- [x] S4 修复完成

**现象**：展开轨道节点间连线为 `::before`、`height:1px`、背景 `rgb(231,235,237)`（浅灰，对白底对比约 1.2:1），10 节点流水线在视觉上断开。视觉模型：「不仔细看容易以为节点是独立悬浮的」。

**修复方向**：加粗至 2px、提升颜色对比（已走完段用阶段成功色，未走段用边框灰 `rgb(201,209,215)` 一级）；如结构允许可将已完成段渲染为实色连接。位置：client.js 展开轨道连线 CSS（`::before`）。

**验收标准**：1440×900 截图中节点连线肉眼清晰可见；深色主题下同样可见。

### M-B 打回次数输入框值不可见

- [x] M-B 修复完成

**现象**：`input[type=number]` `value=""`，仅有 placeholder「默认 3 次」——生效值（默认 3 还是用户上次输入）界面上看不到。

**真实宿主证据**（DOM 实测）：value 为空字符串。

**修复方式**：value 显式回显生效值——未设置时用服务端默认 3（`lib/core/pipeline.js` `DEFAULT_MAX_REVIEW_ATTEMPTS`，客户端带注释同步）；清空输入即恢复默认（保存不落显式字段，`undefined` 时服务端继续用默认）。

**验收标准**：打开设置页，打回次数输入框显示当前生效数值。

- [x] M-C 修复完成

**现象**：输入框 330×56、占位文案 41 字（超出可视宽度被截断）、发送按钮 38×38 禁用态用 ink 色弱化，禁用原因无可感知提示。

**验收标准**：占位文案完整可见不截断；禁用态 hover 有解释。
