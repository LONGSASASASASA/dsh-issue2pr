# 二期原型落地实施计划

创建日期：2026-09-10
依据：[紧凑工作台原型](./issue2pr-compact-prototype.html) 与 [设计说明](./issue2pr-compact-prototype.md)（交互原型 04），及同日评审结论。
规则：每完成一项将 `- [ ]` 改为 `- [x]`，并在文末「完成记录」表追加一行（日期 / 项 / 提交 / 验证方式）。每批完成后同步 [change-log](../../change-log.md)。

## 评审已确认的决策

1. 事件表六列 → **四列**：去掉「状态」「详情」两列，整行可点即详情入口。
2. 事件支持**行内展开**（完整内容就地展开/收起），弹窗只留给长内容、复制、原始记录。
3. **单轮实现**：当前不支持多轮，P6 记录按「输入 → 执行过程 → 输出」一轮呈现；composer 不做。
4. 门禁失败原因分两层：前端先做「查看证据」跳转 + patchEvidence.errors 直显；2026-09-14 用户确认修复验收误判后，新增逐项 `reasons` 和真实证据判定，见第⑧批。
5. 状态列整体去除：统一原始值原则，缺失显示 `—`，不做中文状态映射；仅 result 帧有原生结果时在名称旁显示原值。
6. 全部产物**统一弹窗**形态。第⑦批曾保留「展开到整页」，用户随后明确阶段文件也不跳页；第⑨批取消整页分支，全部产物、阶段产物、输入包、日志源文件、证据和复核历史共用文件弹窗。
7. 流程节点间距与连线缩短（纯 CSS）。
8. 时间线写入补全日期（`YYYY-MM-DD HH:MM:SS`），展示只显时分秒、悬停见完整；旧格式兼容解析。

## 范围外（明确不做）

- 多轮对话与 composer 补充输入（外部执行器会话续接不支持）
- 状态/类型的中文枚举映射
- 协议样例页签（评审演示用途）
- 「正在查看 Px」常驻提示；任务说明原不做，2026-09-14 按用户截图对齐时调整为仅展示已有 P1 现象字段（见第⑥批）
- P11 gate `reasons` 后端契约原在范围外，2026-09-14 已获用户确认并纳入第⑧批
- P1/P3/P4/P5/P7/P8/P9 阶段页重设计（原型范围外）
- P2 代码证据 snippet（真实数据无此字段，不伪造）
