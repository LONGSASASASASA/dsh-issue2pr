更新日期：2026-09-10  
原型版本：交互原型 04

## 1. 文件与用途

- [打开紧凑工作台原型](./issue2pr-compact-prototype.html)：独立 HTML，样式、脚本和模拟数据内嵌，可直接用浏览器打开，无须安装依赖或构建。
- [产品与工程主设计](../issue2pr-studio.html)：长期产品与工程规划，继续位于设计目录根部。
- [一期 V9 原型](../一期原型/issue2pr-ui-prototype.html)：原有原型的独立归档，不由二期整体替换。
- [设计目录索引](../README.md)：一期、二期和主设计的入口及关系。

本原型的维护入口为本目录的 HTML 和本文。`.tmp/ui-review/compact-studio.html` 是此前评审使用的临时副本，不作为后续维护入口。旧的本地预览服务仍读取临时副本，更新正式归档后应直接打开本目录文件。

原型不连接 DSH、Claude Code、Codex 或真实任务。发送补充要求、复制、下载、生成回放及产物预览均围绕内嵌演示数据。直接通过本地文件打开时，剪贴板能力取决于浏览器权限；不可用时有提示，可在内容区选择文字复制。页面刷新会重置演示会话状态。

### 1.1 本期设计边界：涉及什么

二期是**任务详情中执行过程与证据阅读体验的局部设计**，不是整个工作台或流水线的全面重设计。具体边界如下：

| 范围 | 二期涉及的设计 | 本原型提供的程度 |
| --- | --- | --- |
| 任务详情的阅读框架 | 任务头部、紧凑阶段导航、阶段内容区、信息密度 | 静态布局及 P2/P6/P11 切换演示 |
| P2 检索结果 | 文件、职责、置信度与证据相邻展示，减少嵌套缩进 | 模拟候选文件及详情 |
| P6 委派执行记录 | 每轮输入、执行事件、输出；事件六列单行；筛选、预览、详情 | 内存模拟事件和补充轮次，不调用 Agent |
| 通用阅读弹窗 | 详情/原始记录、全文搜索、复制、下载、焦点恢复、边缘留白 | 对已加载模拟数据可交互；不是所有文件类型的通用编辑器 |
| 产物查看 | 节点文件预览、全部产物目录树与右侧预览、关联文件单层打开 | 内嵌示例文件，不读取真实工作区文件 |
| P11 交付展示 | 门禁密度、证据说明、执行完成与验收通过的区分 | 模拟门禁结果，不重新定义验收规则 |
| 跨执行器的显示适配 | 原始类型、字段来源、缺失值、采集时间标识、开放内容区块 | 协议结构样例与接口建议，不代表各执行器已经接入 |
| 响应式和主题 | 单行日志区域横向滚动、弹窗边距、浅色/深色 | 已展示和检查的原型样式 |

只有本表列出的阅读与展示行为是二期的直接设计范围。导航、项目名、任务状态等用于解释页面上下文；出现这些元素不等于其背后的完整功能属于本期。

### 1.2 不涉及什么

- **不重设计整站**：项目管理、任务列表、新建任务、设置、账户、权限配置、全局导航及 DSH 会话页不在本期范围。侧栏仅作上下文占位。
- **不完整覆盖所有阶段**：P1、P3、P4、P5、P7、P8、P9、P10 的独立详情页面没有在本原型中设计完成；P11 引用相关证据不等于覆盖这些阶段的页面。
- **不改变执行语义**：任务调度、阶段状态机、真实工具审批、多 Agent 编排、重试策略、节点回退执行、补丁应用与回滚、门禁判定及交付规则不由此原型修改。
- **不实现流程历史拓扑**：异常重试、P10 分析、节点回退的完整历史图仍需独立设计与验证。保留这些历史的原则不等于本原型已有历史图能力。
- **不接入真实执行器**：Claude Code/Codex 样例不构成 SDK/CLI 兼容性承诺，不新增 Codex 执行器，不实现真实会话续接、思考采集、权限决定或补充输入投递。
- **不实现日志后端**：采集、持久化、订阅、跨事件关联、断线恢复、分页、虚拟列表、服务端搜索及海量日志性能验证均未实施。第 7 节仅说明正式接入应满足的条件。
- **不实施工程交付动作**：不修复正式页面代码、不修改 `client.js` 或执行器、不执行真实补丁、测试任务、提交、PR 创建、发布或部署。
- **不替代主规格或一期全量设计**：二期只细化上述局部范围。一期中未讨论的页面和主设计中的长期能力，不能推定已被二期废弃或完成。

### 1.3 设计约束与实施授权的区别

字段保真、事件关联、内容完整性以及三种重试/轮次层级，是为了让这套界面能够忠实展示真实数据而提出的约束。它们属于**后续接入前需要核验的条件**，不是本次已实现的后台能力，也不构成批量改造后台的授权。

后续若开始正式开发，应另行列出实施页面、执行器、接口、状态规则和验收用例。本期批准与归档仅确认原型的展示方向；不能据此一次性实施整份主设计或本文中的所有后续建议。

## 2. 要解决的问题与最终决定

原页面存在字段标签与内容相距过远、层层嵌套后缩进过大、流程头部占用较多高度、日志和操作入口重复占空间等问题。P6 输入与过程分散在多层标签中，也不利于理解多轮交互。

本轮最终决定如下；早期原型的“四行预览”和“两行执行事件”已被单行方案取代。

| 对象 | 最终展示规则 |
| --- | --- |
| 页面整体 | 紧凑任务头部、可展开流程导航、明确阶段内容区 |
| P2 阶段结果 | 按候选文件组织，文件名、职责、置信度和证据相邻呈现 |
| P6 对话结构 | 每轮按“输入 → 委派 Agent 执行过程 → 输出”排列 |
| 执行事件 | 时间、动作类型、名称、内容、状态、详情，严格六列单行 |
| 执行事件操作 | 每行仅一个详情入口；复制、工具输出等操作进入弹窗 |
| 长内容 | 列表显示有限预览，详情读取完整内容；取消主页自动换行开关 |
| 类型 | 可扩展，保留来源类型与层级，不建立封闭的中文类型列表 |
| 缺失字段 | 显示 `—`；不为填满布局而生成名称或成功状态 |
| 全部产物 | 单个弹窗内左侧目录树、右侧文件预览 |
| 弹窗 | 统一阅读结构，保留屏幕边缘留白和内容内边距 |
| P11 交付 | 紧凑门禁卡片，区分执行结束、Agent 回复完成与验收通过 |

## 3. 页面与流程导航

任务名称、总体状态和阶段导航位于顶部。默认流程导航紧凑展示，可展开查看阶段编号。阶段选择切换内容，不跳转到 DSH 会话页。

原型重点实现 P2、P6、P11，其余阶段按钮保留位置但禁用，并提示评审范围。禁用仅是原型覆盖范围，不是正式产品应禁止查看这些阶段的决定。

**本原型没有实现完整的异常重试、P10 失败分析和节点回退历史拓扑。** P6 的工具失败及恢复事件可查看，但不能将其等同于流程级历史图。正式接入需分别记录：

1. 同一次工具调用的失败与重试。
2. 同一阶段执行内的多轮输入与输出。
3. 流水线打回节点后产生的新阶段执行。

后续流程历史应引用具体执行标识，保留发生顺序和关联原因，不能仅以当前节点状态覆盖旧记录。这是待实施设计，不属于本次归档新增能力。

## 4. 六列单行事件

```text
时间      动作类型          名称              内容预览                    状态    详情
20:56:12  approval.decided  请求文件修改权限  请求权限 → 等待决定 → 批准… 已批准  详情 ↗
```

上例来自模拟数据，`approval.decided`、中文名称和批准过程不构成 Claude Code 或 Codex 的通用原始协议。

### 4.1 布局尺寸

- 事件行高固定为 **34px**；列标题高 30px。
- 六列依次为 `72px / 210px / 140px / 自适应 / 64px / 44px`，内容列最小 160px；列间距 12px，左右内边距 12px。
- 日志表最小宽度 900px。窄屏在日志区域内横向滚动，保持六列单行，不使整个页面横向溢出。
- 类型和名称限宽省略，可通过悬停或详情读取完整值。状态不与内容混在同一文本中。
- 输入和最终输出保留为轮次中的独立消息块，预览最多两行；这不改变执行事件严格单行的规则。

### 4.2 预览与操作

内容预览最多 120 个 Unicode 码点，包含省略号。预览压缩连续空白和换行，按列宽继续做视觉省略；详情保留原文换行和完整文本。120 是原型显示上限，不是存储截断长度。

每条事件仅有一个可聚焦的“详情”按钮。短内容即使已全部显示，仍可进入详情复制或下载。主页不再提供单独的“工具输出”“复制全文”入口，也不提供自动换行开关。

类型筛选由当前实例的事件样例动态生成，支持未识别的扩展类型；全文搜索覆盖已载入的事件内容、参数、结果和输入输出，不只搜索可见预览。正式分页接入时，需要实例级类型集合和服务端搜索，不能将当前页误称为全量。

## 5. 统一详情弹窗

### 5.1 内容组织

| 区域 | 内容与行为 |
| --- | --- |
| 标题 | 有名称则显示名称；名称缺失时使用类型作为弹窗标题，列表名称仍为 `—` |
| 摘要 | 类型、时间、状态；无状态时明确提示未提供 |
| 执行归属与字段来源 | 可折叠，展示来源、事件标识、实例归属及字段提取说明 |
| 详情视图 | 按实际内容生成输入/参数、正文、输出/结果、其他字段、关联产物等区块 |
| 原始记录视图 | 保留收到的结构或原始文本；协议样例不注入伪造的源时间和状态 |
| 工具栏 | 搜索、前后匹配、复制全部、下载 |
| 内容区块 | 每块可单独复制；缺失的区块不占位 |
| 底部 | 完整性提示、可用的生成回放控制、关闭返回原位置提示 |

“详情”和“原始记录”是同一弹窗的两个视图。正文短长不影响可用操作，未知字段也能作为其他字段阅读。

复制范围要明确：区块复制仅复制本区块；“复制全部”复制带区块名称的全部详情；原始记录视图的“复制 JSON”复制序列化原始结构。回放期间提示复制已生成内容，不能将局部内容标成全文。

搜索在当前视图的已加载内容中高亮并定位。关闭弹窗恢复触发入口的焦点及背景滚动位置。持续生成演示可以暂停跟随，用户搜索或向上阅读时不应强制把视口拉到底部。

### 5.2 单层弹窗与产物

- 节点产物可以直接打开文件预览。
- “全部产物”只打开一次弹窗：左侧目录树切换文件，右侧直接更新预览。
- 从事件详情打开关联产物时，在当前弹窗内替换内容，提供“返回事件”；切换文件原始视图也保留返回入口。
- 原型保留节点文件的简易预览；统一详情的分块复制主要覆盖输入、输出和执行事件。不能将本原型理解为所有文件查看器能力都已统一实现。

### 5.3 留白与尺寸

桌面弹窗外侧至少保留 32px，窄屏左右至少保留 20px。详情弹窗宽度上限约 960px，内容高度受视口限制，正文在弹窗内部滚动。

桌面正文左右内边距 24px，窄屏 18px；统一圆角为 12px。标题、工具栏、正文与底部保持一致的左右对齐关系。产物浏览器也遵循外侧留白约束。

## 6. 原始字段与适配原则

六列是展示结构，不是跨执行器的共同原生字段契约。正式接入时按执行器、协议与版本进行适配，保留提取路径，不靠字段名猜测所有事件。

| 字段 | 提取规则 | 缺失与补充 |
| --- | --- | --- |
| 时间 | 优先读取源事件发生时间 | 无源时间时记录采集时间；用 `*` 标记并在详情注明；两者分别存储 |
| 类型 | 读取原始 `type`、`subtype`、内容块类型或协议方法名 | 组合展示时保留各自路径；无类型时 `untyped` 属界面兜底 |
| 名称 | 读取实际工具名等对应字段 | 缺失显示 `—`，不编造一个中文动作名 |
| 内容 | 读取正文、参数、结果或错误等真实内容块 | 无结构日志仍可展示原文；解析失败不应丢弃 |
| 状态 | 原生状态优先；仅依据明确协议事实派生 | 缺失显示 `—`；收到输出或 item 结束不等同于任务成功 |

详情应区分原始值、采集补充值、派生值、模拟值和缺失值。类型不做中文枚举映射，不等于省略数据适配层。

### 6.1 协议样例

原型的“协议样例”单独展示，不属于上方 Claude Code 模拟实例：

- Claude 内容块：外层 `assistant`，块类型 `tool_use`；从块中提取 `name` 和 `input`，不将工具调用发出解释为已成功。
- Codex `exec --json` 消息：外层 `item.completed`，内层 `agent_message`；名称、状态和源时间可能缺失。
- Codex 命令事件：`item.started` 与 `command_execution`，保留 `item.command` 和 `item.status`。
- 非结构化日志：保留字符串原文，使用 `untyped` 兜底，不推断状态。

这些是协议结构节选和模拟值，不是完整协议模式或真实执行记录。Codex App Server 的请求/响应方法与 `exec --json` 不同，接入时应分别处理。

参考：[Claude Agent SDK 类型定义](https://code.claude.com/docs/en/agent-sdk/typescript)、[Codex 非交互 JSON 事件](https://learn.chatgpt.com/docs/non-interactive-mode)、[Codex App Server](https://learn.chatgpt.com/docs/app-server)。本轮字段核对日期为 2026-09-10；实际接入仍应按安装版本验证。

## 7. 后续统一事件协议建议

以下是生产接入的目标协议，**不是原型已经实现的完整后端接口**。原型当前使用内存事件注册表和开放的 `sections[]` 渲染内容；未实现服务端分页、持久化、真实订阅或跨执行器关联。

| 字段 | 语义 |
| --- | --- |
| `schemaVersion` | 我方展示协议版本，与执行器版本分开 |
| `id`、`sequence` | 稳定事件标识、同一事件流内的顺序；不能仅按时间字符串排序 |
| `timestamp`、`receivedAt` | 源时间与采集时间，分别记录 |
| `source` | 执行器、接入协议及可获取的版本 |
| `type`、`typePath` | 原始类型及提取路径；多层类型可用结构表达 |
| `title`、`status` | 可选名称与状态；缺失允许为空 |
| `context` | 任务、阶段、阶段执行、实例和轮次标识 |
| `relations` | 工具调用、父任务、重试和关联产物等标识 |
| `sections[]` | 开放内容区块，包含 id、label、format、content 或读取地址、完整性 |
| `provenance` | 字段属于原始、采集补充、派生或缺失，以及提取依据 |
| `raw` 或 `rawRef` | 原始事件/文本，或其可读取的持久化位置 |

约束：

1. 工具调用和结果通过明确调用 ID 关联；无关联标识时保留独立记录，不按相邻位置强行合并。
2. 文本增量和进度可以更新同一展示项，但保留原始帧与顺序；失败、重试、取消及人工决定不被后续成功覆盖。
3. 内容完整性区分完整、部分、持续接收、源头截断和加载失败。用户侧预览截断与源头丢失不能混淆。
4. 超大日志采用按需加载和适当的虚拟列表；复制、下载必须说明覆盖全文还是仅已加载部分。
5. 思考只展示执行器实际公开提供的原文或摘要，并标注性质；未提供时不补写思考过程。
6. 原始文本与 JSON 以安全文本方式呈现；不能将日志中的 HTML 或脚本直接作为界面执行。

## 8. 当前代码事实与接入边界

截至本轮核对，[执行器注册表](../../../lib/delegate/executors/index.js) 注册 `claude-code` 和 `dsh-agent`，没有独立的 Codex 执行器。

[Claude Code 执行器](../../../lib/delegate/executors/claude-code.js) 将原始 stdout 另行写入日志。[格式化时间线](../../../lib/delegate/executors/agent-timeline.js) 会对镜像内容截断、整理换行，并跳过部分帧。因此不能把镜像当作原始记录，也不能仅因镜像缺少内容就断言原始 stdout 已丢失。是否具备完整历史还需检查实际落盘数据及异常场景。

本轮只归档原型和设计说明，不修改 `client.js`、执行器、正式日志协议、测试或变更日志。后续实施需要单独明确范围，并基于现有代码逐点推进。

## 9. 评审路径与验证记录

建议按以下顺序体验：

1. P6 查看六列单行，筛选 `approval.decided`、`tool_use` 或未知扩展类型。
2. 打开短事件详情，分别复制区块与全部内容；打开长思考，搜索“兼容性边界”。
3. 查看工具参数和输出，切换原始记录，关闭后确认返回原事件。
